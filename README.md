# Lumo — AI-КЛИЕНТ-СКАУТ v2.6.1 (GitHub Pages)

> **v2.6.2 (2026-09-15):** починен реальный поиск по отраслям — фильтр ОКВЭД переведён на
> групповые коды (`XX.Y`), слова-ключи стали префиксными основами (см. «Реальный поиск компаний»).

Самодостаточное single-file приложение: весь код, стили и данные — в одном `index.html` (~1,1 МБ).
Сборки, зависимостей и бэкенда нет. База приложения хранится в `localStorage` браузера и привязана
к адресу сайта (origin). Внешний API — только `suggestions.dadata.ru` (ключ вводится пользователем
в настройках и хранится в его браузере).

## Состав репозитория

| Файл | Назначение |

## Деплой за ~5 минут (без CLI)

1. Создайте новый **публичный** репозиторий на github.com → *New repository*.
   Имя выберите неброское и окончательное, например `lm-ws-7q2`
   (адрес сайта = `https://<ваш-логин>.github.io/lm-ws-7q2/` — см. «Важно» ниже).
2. Загрузите файлы сайта **в корень репозитория**:
   *Add file → Upload files* — перетащите `index.html`, `404.html`, `robots.txt`,
   `README.md`, `VERSION.json`. Commit → *Commit directly to the `main` branch*.
   > Этого достаточно. Скрытые файлы (`.nojekyll`, `.github`) для основного способа НЕ нужны —
   > macOS Finder их прячет и при перетаскивании не отдаёт, это нормально.
3. **Settings → Pages** (в репозитории):
   - *Build and deployment → Source:* **Deploy from a branch**;
   - *Branch:* `main`, папка `/ (root)` → **Save**.
   - Кнопки «Configure» у предложенных воркфлоу (Jekyll / Static HTML) нажимать не нужно.
4. Через 1–2 минуты сайт жив: `https://<ваш-логин>.github.io/<имя-репозитория>/`
   (адрес также виден в Settings → Pages). Каждое изменение файлов в `main`
   автоматически публикуется заново за ~1 минуту.

### Необязательно: автодеплой через GitHub Actions

Понадобится только если хотите деплой воркфлоу вместо деплоя из ветки.
Скрытые файлы для этого можно создать прямо в браузере, без Finder:
*Add file → Create new file* → в поле имени ввести `.github/workflows/deploy.yml`
(слэши сами создадут папки) → вставить содержимое файла
`.github/workflows/deploy.yml` из этого пакета → Commit. Затем
Settings → Pages → Source: **GitHub Actions**.
(Полезно также создать пустой файл `.nojekyll` тем же способом — отключает Jekyll;
без него Jekyll наши файлы просто копирует как есть, ничего не ломая.)

## Реальный поиск компаний (ЕГРЮЛ через DaData)

Важно не путать два места на экране Discovery:

- **Список компаний по отраслям на самом экране** — это ВАША база (стартовый набор,
  встроенный в сборку). Он не обращается к реестру и не может показать больше, чем в нём есть.
- **Блок реального поиска** (поля «отрасль / регионы / города», чекбокс ОКВЭД и кнопка
  **«Найти реальные компании»**) — вот это живой запрос к ЕГРЮЛ через DaData.

Порядок работы:

1. **Ключ DaData** (без него реальный поиск не запускается): https://dadata.ru/api/ →
   регистрация → ключ «Подсказки» (бесплатно, 10 000 запросов/день) → в Lumo:
   Настройки → «Источники данных» → вставить ключ (хранится только в вашем браузере).
2. На экране Discovery в блоке реального поиска выберите **отрасль** и **регионы**
   (можно несколько; по умолчанию стоит домашний регион — поэтому без выбора регионов
   выдача была узкой). Чекбокс **«отраслевая выборка по ОКВЭД»** включён по умолчанию.
3. Нажмите **«Найти реальные компании»**. Поиск идёт по двум осям (v2.6.2, выверено по живому API):
   - **префиксные основы названий** отрасли («транс», «логистик», «перевоз», «мед», «клиник»…) —
     DaData понимает частичное совпадение, поэтому ловятся и брендовые имена
     («ТрансСервис», «МедГарант»), а не только компании со словом «транспортная» в названии;
   - **серверный фильтр по групповым кодам ОКВЭД** отрасли (формат `XX.Y`: «49.1», «56.1», «86.2») —
     отсеивает шум от частичных совпадений. Важно: двузначные коды («49», «56») API не матчит,
     а пустой запрос с фильтрами возвращает 0 (Suggestions — ввод с подсказками, не каталог).
   За запуск тратится до 6 keyword-запросов на регион-группу (лимит шагов 12).
   До 60 карточек в выдаче (параметр count), дедупликация по ИНН.
4. Результат: до 60 карточек (счётчик «count»), сортировка по сотрудникам; кнопки
   добавляют компанию в базу или добавляют всё разом. Дальше — «Глубокий аудит» /
   «Скопировать промпт» для анализа во внешней модели (Qwen и др.), экспорт CSV/JSON.

Подсказки:

- Свободный запрос в поле «q» перекрывает словарь отрасли («перевозки Ижевск»).
- Режим городов: выберите города — поиск пойдёт по каждому с КЛАДР-фильтром региона.
- Лимит шагов поиска — 12 запросов за запуск; при многих регионах часть слов урезается
  (интерфейс предупредёт «часть регионов не охвачена»).
- Счётчик израсходованных запросов за день — Настройки → «Источники данных».

## AI-гипотезы открытого следа (v2.7)

Задача: полуавтоматически привязать сайт, ВКонтакте, соцсети, ЛПР и контакты из открытых
источников, не нарушая канон «след не выдумывается». Браузерное приложение не может само
обойти VK/hh/карты (CORS), поэтому контур такой:

1. Карточка лида → **«Глубокий аудит»** (или AI-мост, действие `SCOUT_AUDIT` / `SCOUT_RECHECK`).
2. В поле RAW (Шаг 2) вставьте сырьё из открытых источников: HTML страницы сайта, текст
   страницы/сообщества ВК, текст вакансии hh, сниппеты поисковой выдачи — что удалось скопировать.
3. Шаг 1 → **«Скопировать промпт»** → в чат Qwen. Промпт теперь просит модель вернуть,
   помимо аудита, ключи `footprint_hypotheses` и `verify_queries`:
   - `source:'raw'` — значение прямо цитируется из вставленного сырья (сайт, сообщество, контакт, ЛПР);
   - `source:'hypothesis'` — только как гипотеза для ручной проверки, без выдуманных точных URL
     (вместо неуверенного URL модель обязана дать поисковый запрос в `verify_queries`).
4. Ответ-JSON → Шаг 2 → применить. Гипотезы падают в `lead.aiFootprint` со статусом
   **«НЕ ПРОВЕРЕНО»** и появляются в модалке **«Разбор цифрового следа»**: по каждой — кнопки
   «Копировать», «Отметить проверенным» (после вашего клика по ссылке и ручной проверки),
   «Снять»; ниже — список поисковых запросов «Копировать запрос» для верификации вручную.
5. Гипотезы не меняют Score, стадию и факты карточки: фактом след становится только после
   вашей отметки «проверено» (или через штатный разбор HTML сайта).

Авто-часть, которая работает уже без Qwen: обогащение по ИНН (DaData) — руководитель (ЛПР),
сотрудники, выручка ФНС, ОКВЭД, МСП. ВКонтакте из браузера не парсится в принципе
(API не отдаёт CORS-заголовок) — только через гипотезы + ручную проверку.

## Простой режим (v2.8)

Приложение перегружено? Включён **Простой режим** (по умолчанию, сохраняется в настройках):

- спокойная светлая тема: крупнее шрифт, больше воздуха, мягче границы;
- меню 11 → 4 пункта: **Дашборд, Все лиды, Поиск компаний, Профиль и настройки** (+ «Добавить компанию»);
- на дашборде остаются «Ближайшие действия» и «Сейчас в работе»; KPI-плашки,
  «Воронка» и «Коммерческие разговоры» скрыты;
- hint-плашки и информационные врезки скрыты; ошибки и предупреждения видны всегда;
- стены чекбоксов регионов/городов в поиске — компактный блок со прокруткой.

Кнопка **«Полный вид»** в правом верхнем углу возвращает все разделы и панели;
«Простой вид» — обратно. Ничего не удалено: простой режим только скрывает второстепенное.
Ключ DaData в простом режиме доступен через кнопку «Ключ» на экране поиска компаний.

## Enrichment Engine v0.1 (v2.9)

Автоматическое обогащение компании: официальный сайт → соцсети (VK, Telegram, Дзен, YouTube,
Rutube, Одноклассники, Instagram) → публичные email и телефон (режим «Глубоко»).

Поток: **НАЙТИ → ОЦЕНИТЬ → PREVIEW → ПОДТВЕРЖДЕНИЕ → СОХРАНИТЬ**. Ничего не пишется в карточку
без предпросмотра; LOW не применяется никогда, MEDIUM — только с вашей галочкой; существующие
значения не перезаписываются без явного подтверждения (показывается «текущее → найденное»).

- Карточка компании → вкладка «Обзор» → блок **«Контакты и присутствие в интернете»**:
  кнопки «Найти контакты и соцсети» (QUICK) и «Глубоко» (DEEP: + email/телефон со страниц
  / и /contacts), «Последний результат» — открыть preview из кеша.
- Архитектура SEARCH_PROVIDER: v3.0 = **Local SearXNG** на вашем MacBook
  (Lumo → Local Helper `http://127.0.0.1:8765` → SearXNG `http://127.0.0.1:8888`): **0 API-ключей**,
  без платных поисков. Установка: `docs/INSTALL_LOCAL_SEARCH_MACOS.md`, запуск двойным кликом
  `local-search/start_lumo_search.command`, диагностика `status_lumo_search.command`.
  В настройках: статусы «● Подключено / ○ Локальный поиск не запущен / ⚠ SearXNG недоступен»,
  кнопка «Как запустить». Legacy Cloudflare Worker + Brave помечен deprecated и не обязателен.
  Данные, снятые С сайта, не могут иметь confidence выше confidence самого сайта;
  MEDIUM (55–74) в Preview не предвыбирается — только ручная галочка.
- Confidence 0–100 с пояснением причин: название/бренд, город, ИНН (+30), телефон (+25),
  адрес/email-домен; агрегаторы, каталоги, карты, маркетплейсы, вакансии и новости понижаются
  до LOW и официальным сайтом не считаются. Категории: 90+ VERY HIGH, 75+ HIGH, 55+ MEDIUM, иначе LOW.
- Соцсети извлекаются с официального сайта (source OFFICIAL_SITE_LINK, confidence 95),
  недостающие — точечным поиском `site:…` (source SEARCH_RESULT). Share/repost/login-ссылки,
  utm и дубли отбрасываются; главные страниц платформ соцсетью компании не считаются.
- Rate limit: QUICK ≤ 3 поисковых запросов, DEEP ≤ 4; результат кешируется в карточке
  (`enrichment.last`) — автопоиска при открытии карточки нет.
- Provenance: основное поле остаётся строкой; метаданные (value/source/confidence/verified_at/
  manual_confirmed) — в `lead.enrichment.meta`. Backup/restore совместимы: старые копии
  импортируются, новые содержат enrichment.

## Первый запуск

1. База будет чистой — это нормально (новый адрес = новый `localStorage`).
2. **Перенос данных со старого адреса (Netlify и др.):** откройте старый сайт →
   «Резервные копии» → Экспорт JSON → на новом сайте: «Резервные копии» → Импорт.
3. **Ключ DaData:** Настройки → «Источники данных» → вставьте бесплатный ключ «Подсказки»
   (https://dadata.ru/api/).
4. Проверка: экран Discovery → источник «Реестр (ЕГРЮЛ)» → поиск по ИНН/названию.

## Обновление версии

Просто замените `index.html` в репозитории (веб-интерфейс: клик по файлу → карандаш → вставить
новое содержимое → Commit в `main`, либо *Add file → Upload files*). Деплой выполнится
автоматически за ~1 минуту. После обновления откройте сайт и сделайте жёсткую перезагрузку
(**Cmd/Ctrl+Shift+R**).

## Важно (приватность и данные)

- ⚠️ **Адрес = граница данных (origin).** База в `localStorage` привязана к адресу сайта.
  Выберите имя репозитория **до начала работы**: переименование репозитория изменит адрес,
  и заполненная база «останется» на старом адресе (перенос — через экспорт/импорт JSON).
- ⚠️ **Публичный репозиторий = исходник виден всем.** В `index.html` встроены реальные
  контрольные лиды. На бесплатном тарифе GitHub Pages работает только с публичными
  репозиториями, а адрес вида `username.github.io/repo` угадываемее случайного
  `*.netlify.app`. Держите имя репозитория неброским и не публикуйте ссылку.
  (Страницы приватного репозитория — только на платных тарифах GitHub Pro/Team.)
- Поисковики сайт не индексируют: `robots.txt` + `<meta name="robots" content="noindex, nofollow">`.
- Чужие визиты вам не мешают: каждый посетитель работает в своём браузере (своя база, свой ключ).
- Кастомные HTTP-заголовки (как в бывшем `netlify.toml`) на GitHub Pages задать нельзя —
  файл удалён, на работу приложения это не влияет.

## Свой домен (необязательно)

Settings → Pages → *Custom domain* → указать домен; у регистратора добавить CNAME
на `<ваш-логин>.github.io`. HTTPS (Let's Encrypt) выпустится автоматически.
Переезд на свой домен = новый origin = пустая база (перенос через экспорт/импорт).

## Лимиты

- GitHub Pages: 100 ГБ трафика/мес, 1 ГБ на сайт — для одного файла 1,1 МБ практически недостижимо.
- DaData: бесплатный ключ «Подсказки» — 10 000 запросов/день; приложение само считает лимит.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| 404 на корне сайта | Pages не включён (Settings → Pages) или деплой ещё идёт (вкладка Actions) |
| Пустая страница | Жёсткая перезагрузка Cmd/Ctrl+Shift+R; проверьте, что адрес по `https://` |
| Ошибка поиска DaData | Адблокеры режут `suggestions.dadata.ru` — добавьте сайт в исключения |
| Пропала база | Сменился адрес (rename/домен) или очистились данные браузера — восстановите из резервной копии |
